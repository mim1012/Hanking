# 실시간 스트리밍 / 소켓 아키텍처

> SRS webhook으로 방송 상태 전이, Socket.IO + Redis adapter로 멀티인스턴스 확장, FFmpeg fan-out으로 멀티플랫폼 재송출. 라이브 커머스 코어.

## 무엇 / 언제 쓰나
RTMP 방송 + 실시간 채팅/뷰어카운트 + 유튜브/인스타 동시송출이 필요한 라이브 서비스를 만들 때.

## 주의점 / 함정 (dorami 채팅 포렌식 2026-07-06 — 회피할 실패 패턴에 이름)
- **삼중 소켓 진입점 금지** — 소켓 부트스트랩은 한 곳으로. dorami는 main.ts 수동 핸들러+게이트웨이 2개가 공존해 초기화 순서·인증이 반복 파손(`2c2cc97e`가 결국 게이트웨이 제거).
- **인증-게스트 진자** — "게스트 읽기/인증 전송" 같은 정책을 프로젝트 문서에 불변식으로 못 박을 것. 안 박으면 fix가 정책을 왕복시킴(이틀 4회 반전).
- **토큰 만료 소켓사** — handshake-only 인증이면 재연결=재인증. 만료 시 refresh→reconnect 경로를 e2e로 고정해야 함(2~7월 5회 재발).
- **소켓 인증을 앱 전역 auth와 공유** — `authenticateSocket`·refresh 싱글톤을 채팅/시청/HTTP가 공유하면 채팅 fix가 로그인·뷰어카운트를 동반 파손. 공유 파일 수정 시 3종 스모크(채팅 라운드트립·게스트 시청·로그인)를 게이트로.
- **계약을 매직 스트링으로 3곳 복제 금지** — 이벤트 payload·룸 접두사(`live:` vs `stream:`)·placeholder·maxlength(200 vs 500)가 공유 타입 없이 복제돼 조용히 어긋남. shared-types를 실제로 import시켜 컴파일러 백스톱 확보.
- **골든플로우 스펙의 hard assert 검증** — 수신 확인을 `.catch(()=>false)`+로그로 처리하면 게이트가 무력화됨. "스펙이 실패할 수 있는가"를 스펙 추가 시점에 확인.

## 배제된 접근 (dead-end)
- **NestJS ChatGateway로 리팩토링** — 수동 main.ts 핸들러와 충돌, 채팅 연결 실패로 revert(`12649ce3`) 후 게이트웨이 삭제. 진입점 통합 없이 표준화만 시도하면 실패.
- **게스트 compose 임시 fallback** — `15e81b7c` "temporarily allow" → 비인증 전송 구멍 → 이틀 뒤 재강제. 임시 정책 우회는 진자의 연료.
