# 실시간 스트리밍 / 소켓 아키텍처

> SRS webhook으로 방송 상태 전이, Socket.IO + Redis adapter로 멀티인스턴스 확장, FFmpeg fan-out으로 멀티플랫폼 재송출. 라이브 커머스 코어.

## 무엇 / 언제 쓰나
RTMP 방송 + 실시간 채팅/뷰어카운트 + 유튜브/인스타 동시송출이 필요한 라이브 서비스를 만들 때.

## 정본 구현 (canonical) — 전부 dorami
- **SRS RTMP→LIVE 전이(webhook)** — `dorami/backend/src/modules/streaming/streaming.service.ts:982` `authenticateStream` (`on_publish` 콜백, streamKey 검증→`LiveStream.status=LIVE`, expiresAt 48h 연장으로 OBS 재접속 관용). `:1068` `handleStreamDone`(네트워크 flap 대비 지연 오프라인 전환).
- **서비스→소켓 브로드캐스트 싱글턴** — `dorami/backend/src/modules/websocket/socket-io.provider.ts:21` `emitToStreamingRoom` — `@WebSocketGateway` DI 없이 `main.ts:322`에서 단일 `Server` 부트스트랩(3 네임스페이스 `/chat`·`/streaming`·root). Redis adapter `main.ts:361`.
- **멀티인스턴스 Redis adapter + graceful degrade** — `dorami/backend/src/common/adapters/redis-io.adapter.ts:23` — pub/sub duplicate, 실패 시 단일서버 in-memory 모드로 강등(`:75`).
- **뷰어카운트 debounce(방당 초당 1회)** — `main.ts:733` `emitStreamingViewerUpdate` — join/leave 폭주 coalesce로 OOM 방지. 멤버십은 Redis set(`live-viewer-membership.ts`), 끊기면 롤백.
- **FFmpeg 멀티타깃 재송출** — `dorami/backend/src/modules/restream/restream.service.ts:260` `spawnFFmpegForTarget` — 타깃별 프로세스, 비디오 `-c:v copy`/오디오 AAC, RTMPS vs RTMP 분기(`:280`), 지수백오프 자동재시작 3회(`:464`), SIGTERM→5s→SIGKILL. `stream:started`/`stream:ended` 이벤트로 시작/정지(`restream.listener.ts:15`).
