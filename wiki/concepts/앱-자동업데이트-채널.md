# 앱 자동업데이트 채널 (플릿 자가 업데이트 + 감시형 재시작)

> `.exe`/앱을 원격 기기 플릿에 1회 배포하면, 이후 원격 소스(GitHub raw 매니페스트 or git pull)에서 최신 코드를 폴링·교체·재실행하는 자가 업데이트 채널. 재배포 없이 코드를 갱신한다.

## 무엇 / 언제 쓰나
수백~수천 대의 원격 윈도우/안드로이드 기기에서 도는 봇/워커/모듈을, 사람이 각 기기를 만지지 않고 중앙에서 갱신해야 할 때. 두 갈래: (a) **매니페스트 폴링**(버전 JSON 비교 후 파일단위 다운로드), (b) **git-pull**(레포 전체를 `fetch + reset --hard`). 둘 다 "폴링 → 새 버전이면 교체 → 자식 프로세스 재시작"의 슈퍼바이저 루프를 공유.

## 정본 구현 (canonical)
- **매니페스트 업데이터** — `turafic_update/auto-updater.ts:100` — GitHub-raw `version.json` 3분 폴링, `localVersion.timestamp >= remote`면 스킵. 캐시 버스팅 fetch(`?t=${Date.now()}`, `:303`)로 CDN 캐시 우회.
- **원자적 파일 스왑** — `turafic_update/auto-updater.ts:301` `downloadFile` — `.tmp`로 받아 기존을 `.bak` 백업 후 `fs.renameSync`로 원자 교체(`:328`). 반쯤 쓰인 바이너리를 절대 남기지 않음.
- **그레이스풀 자식 재시작** — `turafic_update/auto-updater.ts:236` `restartRunner` — SIGTERM → 5초 뒤 SIGKILL → 재기동. 감시형 장기 자식에 재사용.
- **git-pull 릴리스 채널(대안)** — `turafic_update/launcher.ts:268` `gitPull` — `git fetch origin main` + `git reset --hard origin/main`(초기 `git clone --depth 1` `:243`). 파일단위 HTTP 대신 레포 델타를 git으로.
- **슈퍼바이저 루프** — `turafic_update/launcher.ts:505` — `while(true)` 러너 실행 → 종료 시 대기 → 재기동 전 `gitPull`. 크래시-재시작 + 재시작시-업데이트를 한 루프로.
- **플릿 노드 자가구성** — `turafic_update/config.ts:80` `loadConfigAsync` — `os.hostname()`으로 관제 DB(Supabase)에서 이 기기의 역할(`nodeType`)을 조회, env>DB>파일>기본값 폴백.

- **sellermate rankchecker 이중 워치독 — 사이클 고착 + OTA 강제적용 분리 (2026-08-25, v0.4.56)** — 스캔 루프가 특정 상태(WARMUP)에 갇히는 사고와, 그 상태에 갇힌 기기가 정상 OTA 체크 지점(IDLE 재진입)에도 영영 못 돌아와 업데이트를 못 받는 사고를 독립 타이머 2개로 분리해 잡는다. 정본 — `sellermate_naver_place_all/rank-check/android-app/app/src/main/java/com/navertraffic/rankchecker/RankWorkerService.kt`.

  - **독립 OTA 강제적용 워치독** — `checkOtaIndependently():257-289`가 `otaWatchdogRunnable:97-100`(자가 재예약 `postDelayed`, `telemetryState` 미참조)로 10분마다(`OTA_WATCHDOG_INTERVAL_MS:754`) 최신 릴리스를 조회한다. 낙후를 처음 감지하면 시각만 기록하고(정상 스캔 루프의 IDLE 경계 OTA 체크가 먼저 잡을 기회를 준다), 낙후가 1시간 이상 지속되면(`OTA_FORCE_APPLY_AFTER_MS:755`) 스캔 상태와 무관하게 `OtaUpdater.forceInstall()`로 root 강제 설치(`Release.kt:67`→`installWithRoot():131,144` 우선, 실패 시 PackageInstaller 폴백).
  - **named failure(구버전 한계)** — OTA 체크가 스캔 루프의 IDLE 재진입 경계에만 걸려 있으면, WARMUP 등에서 콜백이 안 돌아와 그 경계를 다시 못 밟는 기기는 영영 업데이트를 못 받는다(`RankWorkerService.kt:94` 주석). 두 워치독을 스캔 상태와 완전히 독립된 타이머로 분리한 이유.

## 주의점 / 함정
- **선언만 되고 검증 안 되는 해시** — `turafic_update/auto-updater.ts:29` `VersionInfo.hash`가 optional로 선언돼 있으나 다운로드 무결성 검증에 **전혀 안 쓰임**(trust-on-HTTPS). MITM/오염 raw 파일을 그대로 실행 → 공급망 위험. 자가업데이트는 반드시 서명/체크섬 검증을 붙여라.
- **`git reset --hard`가 로컬 변경 소실** — 원격 강제 동기라 기기 로컬 수정·상태 파일이 조용히 폐기됨. 상태는 워크트리 밖에 둘 것.
- 폴링 채널은 CDN 캐시에 걸린다 → 캐시 버스팅 쿼리 필수.
- Android OTA는 패키지 교체만으로 접근성 바인딩이 풀릴 수 있다. 업데이트 완료를 설치 성공으로 간주하지 말고 `[[State-Machine-접근성서비스]]`의 바인딩 게이트를 뒤따르게 해야 한다.
- **debug 서명이 PC마다 달라 기존 배포 위 업데이트가 통째로 막힌다** — sellermate rankchecker 2026-08-17: `build.gradle.kts`에 릴리스 `signingConfig`가 없어 `debug.keystore`로 서명되는데, 이 키는 빌드 PC의 `~/.android/debug.keystore`라 **다른 PC에서 다시 빌드하면 서명이 달라진다**. 기존 기기에 깔린 앱(서명 f48b45e) 위에 다른 debug 키로 서명한 새 APK를 얹으면 OTA(PackageInstaller)도 `adb install -r`도 전부 `INSTALL_FAILED_UPDATE_INCOMPATIBLE: signatures do not match`. 원본 배포 keystore가 없으면 재서명 불가 → **uninstall 후 재설치가 유일**(앱 데이터·WebView 세션 초기화, 권한 재부여, ANDROID_ID 기반 workerId 재발급 부작용). 교훈: 플릿에 1회라도 OTA로 굴릴 앱은 **첫 배포부터 고정 릴리스 keystore를 `signingConfig`로 박고 그 keystore를 백업**하라. debug 서명 배포는 재빌드 순간 자가 락아웃된다.
- **OTA 체크가 UI 진입점에서만 돌면 무인 기기는 영영 안 받는다** — 같은 세션: `OtaUpdater.check`가 `MainActivity.onCreate`(MainActivity.kt:44)에서만 호출되는데, 순위체크는 foreground `RankWorkerService`가 UI 없이 수행하므로 무인 운영 중엔 액티비티가 안 떠 OTA 폴링 자체가 안 일어난다. 감시 스크립트의 `monkey`/`am start` 재기동이나 서비스 루프 내 주기 폴링이 없으면 롤아웃을 켜도 반영 0. OTA 폴링은 **UI가 아니라 상시 도는 서비스/슈퍼바이저에 걸어라**. sellermate는 이 교훈을 서비스 루프 폴링(`RankWorkerService.kt:126`)으로 반영함.
- **릴리스 키스토어 custody = OTA의 생명줄** — sellermate rankchecker 정본: 서명 키(`rankchecker-release.jks`, SHA256 `0E059D8B…49BF08`, 2738B)를 원본 + `D:\_secure_backup\rankchecker-keystore\` + `C:\Users\PC_1M\Documents\rankchecker-keystore-backup\` **3중 보관**하고 SHA256로 정기 대조한다. 이 키를 잃으면 위 debug-서명 함정과 동일하게 함대 전체가 재서명 불가→uninstall만 남는다. 「1회라도 OTA로 굴릴 앱은 첫 배포부터 고정 릴리스 keystore + 오프라인 백업 ≥2곳 + 해시 대조」가 규칙. 실기기에서 새 버전이 기존 설치본 위에 `pm install -r`로 올라간 성공 자체가 서명 연속성의 실증(인증서 불일치면 실패).

## 배제된 접근 (dead-end)
- **electron-updater/Squirrel 도입** — 이 플릿은 Electron이 아니라 `pkg` 단일 `.exe`라 프레임워크 업데이터를 못 씀. raw https + `child_process`/`git`으로 직접 구현. GUI 앱이 아니면 무거운 업데이트 프레임워크는 오히려 dead-end.
- **OTA 피드만 올리고 실행 중 플릿을 방치** — Android 앱이 시작/유휴 명령 시점에만 업데이트를 적용하므로, 피드 등록만으로 이미 실행 중인 기기의 반영 시점을 보장할 수 없다. `UPDATE_APP`을 안전한 기기별 명령으로 함께 큐잉하되 대장·제외 그룹·카나리아는 명시적으로 제외한다.
