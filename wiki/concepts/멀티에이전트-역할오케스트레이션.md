# 멀티에이전트 역할 오케스트레이션

> planner/architect/reviewer/verifier 등 전문 역할을 분리해 협업시키는 패턴. 에이전트 인프라 공통.

## 무엇 / 언제 쓰나
복잡한 작업을 역할 분담(계획→구현→검증)으로 처리할 때. 프롬프트 라이브러리·팀 파이프라인을 주워올 것.

## 정본 구현 (canonical)

- **팀 파이프라인** — `oh-my-codex/README.md:38` — `team-plan → team-prd → team-exec → team-verify → team-fix`, tmux 기반.

## 주의점 / 함정
- **포크 워커 머지 위험** — 같은 파일을 변경하는 병렬 포크는 충돌한다. `[parallel]` 태그(공유 가변상태 없음) 유닛만 동시 실행하고, 겹치면 `-Worktree`(tmux 워크트리)로 격리.
- **자가승인 금지** — 작성한 포크가 스스로 acceptance gate를 통과 처리하면 안 된다. 별도 reviewer/verifier 패스가 검증(fable5 §4, [[오케스트레이션-강제-게이트]]).
- **규칙은 소프트 트리거** — 이 워크플로우 규칙은 훅처럼 기계적 발동이 아니라 에이전트 판단 의존. 확정 진입이 필요하면 키워드/스킬로 배선해야 함.

## 배제된 접근 (dead-end)
- **`claude-ns-hub` (pip)** — "원자분해+세션포킹을 무료로 해준다"고 소개됐으나 실제론 폰 모니터링 대시보드+Stone 큐 도구. 두 기능 미제공(resume≠fork), 알파, 텔레메트리 기본 ON, `hub install-global`이 `~/.claude/CLAUDE.md`에 프로토콜 주입 → SSOT 드리프트 유발. 2026-07-08 설치 거부, 두 레버를 네이티브로 흡수. 근거: [[하네스-플러그인-흡수-vs-설치]].
