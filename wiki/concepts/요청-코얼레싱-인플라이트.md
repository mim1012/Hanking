# 요청 코얼레싱 (in-flight dedup)

> 동시에 들어온 동일 키 요청을 하나의 Promise로 합쳐 DB 쿼리를 1회로 줄이는 17줄 유틸. 동시접속 100명 목표를 실질적으로 해결한 단일 패턴.

## 무엇 / 언제 쓰나
캐시 미스 순간 동일 목록/집계 요청이 폭주하는 읽기 경로(디렉토리 목록, 대시보드 집계). `unstable_cache` 등 결과 캐시와 별개로, "캐시 채우는 순간의 중복 실행"을 막는다.

## 정본 구현 (canonical)
- `_wiki/raw/snapshots/massage/src/lib/server/in-flight.ts:1` — `getSharedInFlight(store, key, load)`: Map에 진행 중 Promise를 키로 저장, `.finally()`에서 자기 제거. 호출부는 모듈 레벨 `Map<string, Promise<T>>`를 유지.

## 다른 구현 / 변형
- 결과 캐시(`unstable_cache` + 태그 무효화)와 조합: `_wiki/raw/snapshots/massage/src/lib/server/shop-store.ts`의 공개 목록 경로 — 코얼레싱은 "동시", 캐시는 "시간축" 중복 제거로 역할이 다름.

## 주의점 / 함정
- **키에 모든 필터 파라미터를 포함할 것.** 키에서 필터 하나라도 빠지면 다른 필터 결과가 섞여 나온다 (massage에서는 `JSON.stringify({userId, role, region, q, page, pageSize})`로 구성).
- 에러 난 Promise도 `.finally()`로 제거되는지 확인 — 안 그러면 실패가 키에 고착돼 계속 같은 에러를 돌려준다 (이 구현은 안전).
- 결과를 mutate하는 호출부가 있으면 공유 Promise라 서로 오염됨 — DTO는 불변으로.

## 변형: 키워드 SERP snapshot fan-out (2026-08-17)

동일 검색어를 여러 슬롯이 공유할 때는 외부 SERP 조회만 코얼레싱하고, 결과 저장은 슬롯별로 유지한다. `D:\Project\zero-landing\tools\keyword-pipeline-helpers.mjs:23`의 `createQuerySnapshotCache()`가 정규화된 query를 Promise 단위로 합치고, `:11`의 `findMidRank()`가 하나의 snapshot에서 슬롯별 MID 순위를 다시 판정한다. 호출부는 `D:\Project\zero-landing\tools\keyword-pipeline.mjs:240`에서 전체 `nvMid` 목록을 한 번 읽고 `:366`에서 후보별 report를 만든다.

- 캐시 키는 query다. URL/MID를 전역 결과 키에 넣지 않는다. MID는 snapshot에서 개별 판정하고, 후보 원장과 `landing_keyword_pool` fan-out은 `slot_id + assignment_id + query` 단위로 보존한다.
- 캐시는 한 worker/run 범위다. 여러 프로세스에 걸친 전역 dedup이 필요하면 durable query task + snapshot + fan-out 테이블로 승격해야 한다.
- 같은 query의 HTTP 418/429 snapshot도 후보별 retryable report로 fan-out하되, 외부 재호출은 캐시 수명 동안 막아 retry storm을 줄인다.
