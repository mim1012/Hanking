# 행정동 기반 지역 필터 ("맞춤콜")

> 콜 배차 앱에서 출발지/목적지를 시/도→구/군→동 3단계로 선택하게 하고, 콜의 raw 주소 텍스트를 로컬 행정구역 사전으로 정규화해 Set-containment로 매칭. 좌표/거리 계산 불필요.

## 무엇 / 언제 쓰나
콜/배차 자동화 앱에서 "특정 지역 콜만 받기" 필터를 사용자가 세밀하게(동 단위) 설정하게 하고 싶을 때. 하드코딩된 키워드 목록(예: 인천공항 지명 나열)보다 일반화된 지역 커버리지가 필요할 때.

## 정본 구현 (canonical)
- **데이터 모델** — `touchassist/data/AutoOriginPreferences.java`, `AutoDestinationPreferences.java` — province(시/도)/district-or-city(구·군 또는 시)/dong(동) 3개 `Set<String>`, SharedPreferences 영속화(`AutoOriginPreferencesStore.java:15-43`). dong 선택은 선택사항(구/군 단위까지만 선택 가능).
- **주소 파싱 3단계 캐스케이드** — `touchassist/CallParsingKt.java:507-606`(`parseCallLocation`, 접미사 토크나이저: 시/도/시/구군/동읍면리가 접미사로 원문 분류) → `resolveLocationFromCacheOrJuso`(`:322-396`, 1차 로컬 사전 `LocalAddressResolver` → 2차 로컬 캐시 `AddressCache` → 3차만 Juso 주소 API `runBlocking` 동기 호출). 로컬 사전 hit면 API 자체를 안 탐 — 네트워크는 최후 폴백일 뿐 필수 경로 아님.
- **법정동→행정동 변환** — `AdminDongResolver.java`(`assets/admin_dong_codes.json`), `LegalDongResolver.java`(`assets/legal_to_admin_map.json`) — 둘 다 로컬 내장 JSON, 네트워크 불필요.
- **매칭 알고리즘** — `touchassist/ReservationWatchService.java:40361-40526`(`matchesOrigin`, 목적지도 동일 패턴) — dong 파싱됐으면 Set.contains 정확매칭 → 실패시 `matchDongWithJeFallback`(`:40538-40554`, "제1동"↔"1동") → `matchEupMyeonFallback`(`:40562-40576`, 읍↔면 치환) 순 재시도. dong이 없고 district만 있으면 `"province district"` 문자열 contains 또는 district suffix 매치(`:40498-40525`)로 폴백. **위경도/거리 계산 없음 — 순수 텍스트 Set-containment.**

## 다른 구현 / 변형
- `Vortex/ReservationCall.kt` `INCHEON_AIRPORT_KEYWORDS`/`INCHEON_AIRPORT_DESTINATION_KEYWORDS` — 행정구역 개념 없이 하드코딩 문자열 리스트를 `route.contains(keyword)` 부분매칭. 인천공항 한 지역에만 한정, 사용자 확장 불가. → [[project-Vortex]]

## 주의점 / 함정
- **반경/좌표 필터는 사족이 되기 쉽다** — touchassist는 반경 옵션(`RadiusOption`) UI를 노출하지만 실제 매칭 로직과 완전히 분리된 죽은 기능(별도 `MockListSettings` 클래스에서만 소비). "정교해 보이는 UI"가 실제로 매칭에 쓰이는지 반드시 확인할 것.
- **저장 필드와 매칭 조건의 불일치** — `selectedProvinces`가 저장은 되지만 매칭 함수는 district/dong만 검사(province는 로그용). 필터 UI에 노출된 모든 필드가 실제 판단 로직에 소비되는지 케이스 하나씩 대조 필요.
- **네트워크 폴백의 레이턴시 리스크** — Juso API를 `runBlocking`으로 동기 호출하면 콜 처리 스레드가 블로킹된다. 실시간 배차처럼 지연에 민감한 도메인에서는 로컬 사전 커버리지를 충분히 넓혀 API 호출 빈도를 낮춰야 함.

## 배제된 접근 (dead-end)
- **반경(좌표) 기반 매칭** — touchassist가 UI까지 만들어놓고 실제로는 구현/연결하지 않은 채 방치. 좌표 획득(지오코딩)·거리계산 인프라를 새로 갖추는 비용 대비, 텍스트 기반 행정동 매칭만으로 이미 충분한 커버리지를 얻었기 때문으로 추정.
