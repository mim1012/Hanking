# 네이버 순위 계산 (쇼핑/플레이스)

> 네이버 쇼핑·플레이스 검색 결과에서 특정 상품/업체의 순위를 산출하는 로직. 여러 자동화 프로젝트의 공통 코어.

## 무엇 / 언제 쓰나
새 순위체크/트래픽 프로젝트에서 "몇 페이지 몇 번째" 순위를 계산할 때. 재구현하지 말고 아래 canonical을 주워올 것.

## 정본 구현 (canonical)
- **플레이스 순위** — `sellermate_naver_place_all/place-check/check-place-rank-core.ts:675` (`checkPlaceRank`) — m.search 인라인 리스트 → "펼쳐서 더보기" → 키워드+더보기 list → 타 업종(restaurant/place/hospital/hairshop) 순차 재시도. placeId/타입 URL 파싱은 `parsePlaceUrl:86` (naver.me 단축URL follow 포함), 상호명 클리닝 정규식 `:9`.
- **쇼핑 순위** — `sellermate_naver_place_all/rank-check/` — 공식 `순위 = (page-1)×40 + position`, DOM `data-shp-contents-id`/`chnl_prod_no` 매칭. MID 추출은 extractor 팩토리(`rank-check/extractors/`: SmartStoreExtractor `:22` `/products/(\d+)`, Catalog/QueryParam/Fallback).

## 순위 "효과" 통계 (전략 A/B 판정)
- 정본 — `naver_turafic_samsung/tools/rank-analysis/a-strategy-rank-effect.mjs` (창 중앙값 + 시간 DiD + 상품 클러스터 부호검정), 진입율 기반 판정은 `experiment-result-v2.mjs:118`.
- **순위 피드는 로테이션 크롤이다**(`sellermate_slot_rank_naver_history`: 2026-07 실측 가동 492슬롯 중 하루 85~124개만 갱신). 단일 시점 순위로 전/후를 찍으면 표본이 1/5로 줄고 단일 관측 노이즈가 ±300계단씩 튄다 → **W일 창의 중앙값**을 쓸 것.
- 같은 상품(`mid`)에 슬롯이 여러 개 걸려 있어 슬롯 단위 검정은 과대 유의해진다 → **상품 클러스터 단위**로 묶고 검정.
- 전/후 순위대별로 쪼개면 평균회귀(regression to the mean)가 "31~100위는 크게 상승, 101~300위는 하락"처럼 보이게 만든다 — 인과로 읽지 말 것.

## 쇼핑탭 페이지 전환은 "클릭했다"로 끝내면 안 된다 (2026-08-08)
쇼핑탭은 SPA다. 페이지 번호를 `btn.click()` 해도 목록이 안 바뀌는 경우가 있고, 그러면 **1페이지를 15번 재스캔하고 "600위 내 미발견"으로 오판**한다. 정본 — `sellermate_naver_place_all/rank-check/parallel/parallel-rank-checker.ts`:
- `scrollUntilPaginationVisible:220` — 하단 페이지네이션이 화면에 보일 때까지 스크롤(lazy-load 트리거 겸용). 안 보이면 클릭 자체가 무의미.
- `goToNextPageForProductId:404` — 번호 링크에 `pointerdown/mousedown/pointerup/mouseup/click`을 직접 dispatch(`:469`). Puppeteer mouse/ElementHandle 클릭은 좌표·격리 이슈로 SPA에 미반영되는 사례가 있었다.
- **전환 검증 3중** — 상품 mid 목록 샘플 변화(`sampleShoppingProductKey:196`) OR `active` 클래스의 페이지 번호 OR URL `pagingIndex`. 하나라도 맞으면 전환 인정, 10초 내 셋 다 아니면 실패 반환.
- dead-end: URL의 `pagingIndex=N`을 치환해 직접 `goto`하는 방식. 구버전 `accurate-rank-checker.ts`가 쓰던 방법인데 버튼 클릭 방식으로 교체됐다.
- 쇼핑탭이 `/ns/search`로 리다이렉트되면 `/search/all?frm=NVSCTAB`으로 되돌려 고정(`:157`). 안 하면 DOM 구조가 달라 전부 미발견.

## 주의점 / 함정
- 네이버 쇼핑은 페이지당 40개 기준. 플레이스는 인라인/더보기 페이지 구조가 달라 별도 로직 필요.
- 상호명은 반드시 클리닝(공백/특수문자) 후 매칭.
- `sellermate_slot_rank_naver_history.slot_status_id` = `sellermate_slot_naver.id` (2026-07-30 keyword 4000행 100% 일치로 검증). `slot_sequence` 조인은 6% 불일치 → 쓰지 말 것.
