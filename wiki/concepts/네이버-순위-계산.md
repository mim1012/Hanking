## 순위 "효과" 통계 (전략 A/B 판정)
- 정본 — `naver_turafic_samsung/tools/rank-analysis/a-strategy-rank-effect.mjs` (창 중앙값 + 시간 DiD + 상품 클러스터 부호검정), 진입율 기반 판정은 `experiment-result-v2.mjs:118`.
- **순위 피드는 로테이션 크롤이다**(`sellermate_slot_rank_naver_history`: 2026-07 실측 가동 492슬롯 중 하루 85~124개만 갱신). 단일 시점 순위로 전/후를 찍으면 표본이 1/5로 줄고 단일 관측 노이즈가 ±300계단씩 튄다 → **W일 창의 중앙값**을 쓸 것.
- 같은 상품(`mid`)에 슬롯이 여러 개 걸려 있어 슬롯 단위 검정은 과대 유의해진다 → **상품 클러스터 단위**로 묶고 검정.
- 전/후 순위대별로 쪼개면 평균회귀(regression to the mean)가 "31~100위는 크게 상승, 101~300위는 하락"처럼 보이게 만든다 — 인과로 읽지 말 것.

## 쇼핑탭 페이지 전환은 "클릭했다"로 끝내면 안 된다 (2026-08-08)
쇼핑탭은 SPA다. 페이지 번호를 `btn.click()` 해도 목록이 안 바뀌는 경우가 있고, 그러면 **1페이지를 15번 재스캔하고 "600위 내 미발견"으로 오판**한다. 정본 — `sellermate_naver_place_all/rank-check/parallel/parallel-rank-checker.ts`:
- `scrollUntilPaginationVisible:220` — 하단 페이지네이션이 화면에 보일 때까지 스크롤(lazy-load 트리거 겸용). 안 보이면 클릭 자체가 무의미.
- `goToNextPageForProductId:404` — 번호 링크에 `pointerdown/mousedown/pointerup/mouseup/click`을 직접 dispatch(`:469`). Puppeteer mouse/ElementHandle 클릭은 좌표·격리 이슈로 SPA에 미반영되는 사례가 있었다.
- **전환 검증 3중** — 상품 mid 목록 샘플 변화(`sampleShoppingProductKey:196`) OR `active` 클래스의 페이지 번호 OR URL `pagingIndex`. 하나라도 맞으면 전환 인정, 10초 내 셋 다 아니면 실패 반환.
- dead-end: URL의 `pagingIndex=N`을 치환해 직접 `goto`하는 방식. 구버전 `accurate-rank-checker.ts`가 쓰던 방법인데 버튼 클릭 방식으로 교체됐다. 단 **폴백으로는 여전히 필요** — 위 "pagingIndex URL 폴백" 참고.
- 쇼핑탭이 `/ns/search`로 리다이렉트되면 `/search/all?frm=NVSCTAB`으로 되돌려 고정(`:157`). 안 하면 DOM 구조가 달라 전부 미발견.

## pagingIndex URL 폴백 (2026-08-11 hard-won)
SPA 무력화(네이버가 버튼 클릭은 받되 상품 목록을 안 바꾸는 연성 차단)의 유일한 우회 수단. 정본 — `sellermate_naver_place_all/rank-check/parallel/parallel-rank-checker.ts:887` (`goToNextPageForProductId` 내부). 클릭 후 상품 목록이 10초간 안 바뀌면 `pagingIndex=N` URL로 `page.goto` 재진입. URL 폴백 후 상품 수·보안 페이지 검증(`:912`).
- **이 폴백이 빠지면 2페이지 이후가 통째로 죽는다.** 서버 5대에서 10분간 순위 발견 1건이었던 것이 복원 후 185위까지 정상 추출됨.
- dead-end: 클릭만 반복하며 간격을 늘려보는 방식. 네이버가 DOM에서 버튼 자체를 제거하므로 기다려도 안 된다.

## API 차단 후 ADB Chrome DOM 폴백 (2026-08-23)
ADB 일반 Chrome CDP 러너는 API 응답이 418/파싱 실패하면 직접 fetch 결과를 미발견으로 확정하지 않고, 렌더된 페이지 번호를 실제 CDP 마우스 이벤트로 클릭해 DOM의 `organic_expose_order`와 `chnl_prod_no`를 다시 읽는다. 정본 구현은 `sellermate_naver_place_all/rank-check/android/extract-rank.ts:366`(DOM 페이지 순회)·`:454`(API 실패 분기), 클릭 primitive는 `rank-check/android/cdp.ts:244`(`Input.dispatchMouseEvent`)다. 버튼은 `scrollIntoView(center)` 후 좌표를 읽어야 Android Chrome에서 화면 밖 좌표를 누르는 실패를 피할 수 있다.
- 실기기 카나리: 슬롯 6045 `예초기날`은 3페이지 112위, history id 580332 read-back 일치. API 차단 분기 카나리 슬롯 5485 `바디로션`은 DOM 페이지네이션으로 10페이지 379위, history id 580333 read-back 일치.
- 이 경로는 `rank-check/android/check-android-rank.ts`가 사용하는 **ADB 일반 Chrome** 경로다. `android-app`의 WebView는 외부 Chrome CDP 세션을 공유하지 않으므로, 이 fallback을 검증 없이 WebView APK에 복사해도 같은 결과가 보장되지 않는다.

## 광고 제외 순위 = organic_expose_order (JSON rank) — contents-rank 아님 (2026-08-16 재정정)
"광고를 빼고 순위를 세라"는 요구의 정답 필드는 **`organic_expose_order`**(DOM dtl) = **JSON 오가닉 아이템의 `rank`**다. 실측(웨일 CDP):
- ~~`data-shp-contents-rank`는 광고를 건너뛴 오가닉 연속 번호~~ → **재정정: contents-rank는 lst\*A 광고를 포함한 노출 순번이다.** "베개" 실측에서 선두 lst\*A 광고 2개가 rank 1·2를 차지하고 첫 오가닉이 rank=3(org=1). E2E 검증: 양배추 honestfooddelivery 슬롯 = contents-rank 6위 / **광고 제외 4위**(`_probe-rank-e2e.ts`, 사용자 확인값과 일치). contents-rank 기반이면 상단 광고 수만큼 순위가 밀려 측정된다.
- 상품 카드 1개당 트리플 속성 앵커가 **~4개**(area `lst*N.img/.title/.rv/.purchasecount`, 같은 rank 공유) → 앵커를 직접 세는 방식은 순위를 4배 뻥튀기(10위권 상품이 55위로 측정됨). 세지 말고 필드를 읽어라.
- inventory 규칙: **오가닉=`lst*N`/`lst*C`, 광고=`lst*A`(일반)·`lst*P`(슈퍼적립 '광고+')·`lst*D`**. ~~JSON에서는 `crUrl`/`adcrUrl` 존재가 광고~~ → **정정(2026-08-16 실측): `crUrl`은 오가닉 전 상품(40/40)에 존재. JSON 광고 판정은 `adId`/`adcrUrl`만 유효.** `crUrl` 기준을 쓰면 전 상품이 광고로 오판된다.
- 내 상품이 광고 슬롯(lst\*A/P)으로 매칭되면 순위로 채택하지 않고 오가닉 노출을 계속 탐색.
- dead-end ①: 광고 아닌 앵커를 직접 세는 방식(앵커 4개/상품 중복). dead-end ②: 페이지별 오가닉 개수 누적(`organicSoFar`) — 부분 로드 페이지 하나가 이후 전부 오염. **JSON rank는 전역 오가닉 순번(2페이지=41~)이라 누적 자체가 불필요.**

## 스크롤 없는 순위 추출 = JSON이 정본 (2026-08-16 실측)
DOM 앵커는 lazy-load 실재(스크롤 0회 시 40개 중 상품 5~11개만 DOM 존재) → DOM 경로로는 스크롤 생략 불가. 그러나 **JSON에는 로드 직후 전량이 있다** (웨일 CDP 실측, 브랜치 `prolific-porcupine`의 `rank-check/test/_probe-expose-order.ts`·`_probe-nextdata-deep.ts`·`_probe-page2-xhr.ts`):
- **1페이지**: `__NEXT_DATA__.props.pageProps.compositeList.list` — SSR이라 스크롤 0회에 44개(오가닉 40+삽입광고 4) 전부. 광고는 `adId`/`adcrUrl` 보유(`adsrTypeCd=M12xxx`), 오가닉 `rank`는 1~40 무결번 연속.
- **2페이지+**: `/api/search/all` XHR `shoppingResult.products` — 광고 자체가 안 섞임(40/40 오가닉), `rank`가 41~80 등 **전역 오가닉 순위 그 자체**. 스크롤은 페이지네이션 버튼 노출용 최소한만 필요.
- **JSON rank ↔ DOM `organic_expose_order` 완전 일치** 교차검증 완료(org=4↔rank=4 … org=38↔rank=38). DOM의 `data-shp-contents-dtl`에는 `nv_mid`/`organic_expose_order`(오가닉·카탈로그)/`ad_expose_order`(lst\*A)가 있으나 lazy-load 때문에 JSON이 우월.
- **lst\*P(광고+)는 `pageProps.superSavingProducts` 별도 배열**(compositeList와 id 중복 없음) → 오가닉 계산에서 자연 배제. P 앵커의 `organic_expose_order`는 P풀 내부 순번이라 오가닉 순번과 충돌(둘 다 1로 시작) — DOM으로 셀 때 P를 오가닉에 넣으면 안 되는 이유.
- **카탈로그 하위 판매처 매칭**: `compositeList.list[].lowMallList[]`에 `nvMid`+`mallPid`(=chnl_prod_no)+`chnlType`(STOREFARM 등) 존재 → 스마트스토어 상품이 카탈로그로 묶여도 JSON만으로 매칭 가능.
- 함정: 레퍼러 없는 `/search/all` 직접 goto는 새 프로필+클린 IP에서도 **0초 캡차**(재확인). 진입은 메인→검색→쇼핑탭 클릭(href를 `/search/all`로 교체) 경로 필수.

## 주의점 / 함정
- 네이버 쇼핑은 페이지당 40개 기준. 플레이스는 인라인/더보기 페이지 구조가 달라 별도 로직 필요.
- 상호명은 반드시 클리닝(공백/특수문자) 후 매칭.
- `sellermate_slot_rank_naver_history.slot_status_id` = `sellermate_slot_naver.id` (2026-07-30 keyword 4000행 100% 일치로 검증). `slot_sequence` 조인은 6% 불일치 → 쓰지 말 것.
- **6시간 SLA와 일일 history 게이트 혼동** — `coverage-backfill.ts:103-108`이 오늘 자정 이후 history 존재 여부를 기준으로 백필한다. 하루에 한 번 기록된 슬롯도 6시간 커버리지에서는 stale일 수 있으므로, 운영 주기가 6시간이면 `now-6h` 창과 슬롯별 최신 적재 시각을 별도로 판정해야 한다.
- **미발견 재시도 hot-loop** — 최신 `last_check_date` 우선 정렬은 15페이지 미발견 의심 작업을 큐 앞에 계속 세워 신규 슬롯을 굶긴다. 미발견은 history에 저장하지 않는 것이 맞지만, `next_retry_at`/시도 횟수와 FIFO 또는 retry 전용 큐가 없으면 전체 커버리지가 불균형해진다.
- **활성 상태≠처리 가능** — `status=작동중`만으로 처리 대상 수를 세면 만료 슬롯과 마스터 비활성 슬롯이 섞인다. 만료·마스터 상태·URL 유효성까지 같은 함수로 필터링한 뒤 커버리지를 계산해야 한다.

## Android 앱 WebView → 실제 Chrome CDP 핸드오프 (2026-08-23)

`android-app` 순위 워커는 WebView 직접 fetch를 먼저 믿지 않고, root 권한으로 추출한 `cdp-bridge.dex`를 통해 실제 Chrome 세션의 `/json/list`와 WebSocket CDP에 연결한다. 정본 구현은 `rank-check/android-app/app/src/main/java/com/navertraffic/rankchecker/ChromeDevToolsBridge.kt`, `ChromeDevToolsSocket.kt`, `ChromeCdpRanker.kt`다.

- API 경로: Chrome same-origin `/api/search/all`의 `shoppingResult.products`를 읽고 `adId`를 제외한다.
- API가 418/429, 보안 문서, JSON 오류, products 누락/빈 배열이면 성공/미발견으로 확정하지 않고 `state=DOM`으로 전환한다.
- DOM 경로: 메인 `paginator_list_paging`/`paginator_inner`에서 page2부터 순차적으로 버튼을 찾아 `.click()`하고, `pagingIndex`/활성 페이지를 확인한 뒤 DOM `organic_expose_order`와 `chnl_prod_no`를 읽는다. 추천상품의 `reactiveForyou_pagination`을 generic pagination selector로 잡으면 page3 이후가 끊기므로 피한다.
- URL은 Chrome이 page2 이동 뒤 `adQuery/origQuery/pagingIndex/...&query=`로 정규화할 수 있으므로 exact `?query=`만 요구하지 말고 msearch 호스트 fallback을 둔다.
