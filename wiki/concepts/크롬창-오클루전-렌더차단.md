# 크롬창-오클루전-렌더차단
> visible 콘솔이 Chrome 창을 완전히 가리면 Native Window Occlusion Detection이 렌더링을 스로틀해 "로드 중..."에서 멈춘다 — `--disable-features=CalculateNativeWinOcclusion` + 강제 최전면화로 우회한다.

## 무엇 / 언제 쓰나
FleetAgent류 인프라가 원격 PC의 콘솔/RDP 세션에서 최대화된 자식 프로세스(로그 콘솔 등)를
띄운 채 그 뒤에서 Chrome을 CDP 없이(Win32 입력 + UI Automation만으로) 조작할 때. 페이지
HTML은 `curl`/`Invoke-WebRequest`로는 정상 속도로 받아지는데, 실제 Chrome 창만 "로드
중..."에서 멈추고 UIA 접근성 트리가 비거나(`totalLinks=0`) 서서히만 채워지면 이 문서를
적용한다.

## 정본 구현 (canonical)
- `turafic_update`(round-penguin worktree)
  `engines/pc-strategy-a-nocdp/nocdp-click-engine.ps1:395` — Chrome 실행 인자에
  `--disable-features=CalculateNativeWinOcclusion` 추가(가려져도 렌더링 스로틀 안 걸림).
- 같은 파일 `:12-29` — `Win32Input.Foreground(IntPtr h)`: `ShowWindow(h,5)` +
  `BringWindowToTop(h)` + `SetForegroundWindow(h)` 3연속 호출로 창을 물리적으로 최전면화.
  `:429`, `:445` — Chrome 창을 찾은 직후 이 함수를 호출해, 이어지는 `SetCursorPos`/
  `mouse_event`/`SendKeys` 같은 실제 OS 레벨 입력이 콘솔이 아니라 Chrome에 꽂히게 함.
- 실측 근거: `docs/experiment/2026-08-19-nocdp-mobile-header-standard.md` §8.3 — 2026-08-20,
  VM1(zen-nocdp-01)에서 이 패치 전후로 트라이얼 결과가 `no_click_landed(url_unchanged)`/
  `totalLinks=0`(백지) → `LOGIN_REDIRECT`/`dom_incomplete`(실제 네비게이션 발생) →
  `success_mobile`로 전환되는 걸 확인.

## 다른 구현 / 변형
- 렌더링만 고치고 최전면화를 안 하면 절반만 해결된다 — HTML/UIA 트리는 정상 채워지지만
  물리 클릭이 여전히 콘솔에 꽂혀 `no_click_landed(url_unchanged)`로 실패한다(같은 문서 §8.3
  실측). 두 조치는 서로 다른 문제(렌더링 vs 입력 라우팅)를 고치므로 반드시 같이 적용.

## 주의점 / 함정
- **"HTML은 빨리 오는데 화면만 멈춘다"는 증상이 네트워크/서버 문제로 오인되기 쉽다** — GPU
  유무·CPU·디스크·네트워크 지연을 전부 실측으로 배제하고 나서야 오클루전이 원인임을 특정함
  (`docs/experiment/2026-08-19-nocdp-mobile-header-standard.md` §8.3). 원인 후보를 좁힐 때
  "가려진 창"을 먼저 의심하면 시간을 아낄 수 있다.
- SSH 세션 자체는 화면 캡처가 안 되므로, 이 증상을 눈으로 확인하려면 RDP/Interactive
  예약작업으로 로컬 스크린샷을 찍어야 한다 — 관련: turafic_update Claude 프로젝트 메모리
  `nocdp-fleet-visible-console.md`(이 위키와 별개 시스템, 위키 링크 대상 아님).

## 배제된 접근 (dead-end)
- **오클루전 플래그 없이 콘솔 창을 그냥 최소화/뒤로 보내는 방식은 FleetAgent의 visible
  콘솔이 로그 출력을 위해 계속 떠 있어야 하는 운영 요구와 충돌**해서 채택하지 않음 — 콘솔을
  치우지 않고도 Chrome이 렌더링을 유지하게 만드는 쪽(오클루전 플래그)이 근본 해결.
- **CPU/GPU/디스크/네트워크 튜닝**(무-GPU VM 의심, 디스크 I/O 의심 등)을 먼저 시도했으나
  전부 실측으로 배제됨(`docs/experiment/2026-08-19-nocdp-mobile-header-standard.md` §8.3,
  "GPU 유무/CPU/네트워크/디스크 어느 것도 원인이 아니었음") — 오클루전을 의심하기 전까지
  잘못된 방향으로 시간을 씀.
