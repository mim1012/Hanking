# 원자적 조건부 감소 (오버셀/더블스펜드 방지)

> 락 없이 `updateMany({where:{...gte}, data:{decrement}})` + `count` 검증으로 재고·포인트 동시 차감의 오버셀/더블스펜드를 막는 패턴. dorami 최고의 재사용 자산.

## 무엇 / 언제 쓰나
재고 차감, 포인트 사용, 쿠폰 소진 등 "잔량이 충분할 때만 원자적으로 줄여야" 하는 모든 곳. 비관적 락(SELECT FOR UPDATE) 없이 ReadCommitted에서 안전.

## 정본 구현 (canonical)
- **재고 차감** — `dorami/backend/src/modules/orders/inventory.service.ts:104` `batchDecreaseStockTx` — `updateMany({ where:{ id, status:'AVAILABLE', quantity:{ gte } }, data:{ quantity:{ decrement } } })`, `updated.count===1`이면 성공, 0이면 원인 조회 후 `InsufficientStock`/`SoldOut`. WHERE의 `gte` 재검사가 커밋값에 재평가되어 더블스펜드 방지. 성공 후 `quantity:0`이면 `SOLD_OUT` 전이(`:165`).
- **포인트 차감** — `dorami/backend/src/modules/points/points.service.ts:192` `deductPointsTx` — `updateMany({ where:{ userId, currentBalance:{ gte:amount } }, data:{ decrement } })`, `count===0`이면 `INSUFFICIENT_POINTS`(`:221`). 재고와 완전히 동일한 패턴. 적립은 `:129` `addPoints`가 `increment`로 원자적.

## 함께 쓰는 동시성 기법 (dorami)
- **다건 락 순서 정렬로 데드락 방지** — `orders.service.ts:210-222` — 카트를 productId→variantId 오름차순 정렬 후 락 획득(두 사용자가 항상 같은 순서).
- **재시도 트랜잭션 밖에서 ID 생성** — `orders.service.ts:154-159` — orderId를 tx 밖에서 1회 생성해 재시도 시 시퀀스 갭/중복 방지. `withOrderTransactionRetry`(P2034/P2028 재시도, `:161`).
- **예약번호 Redis INCR 원자 채번** — `reservation.service.ts:83` + `@@unique([productId, reservationNumber])`.
