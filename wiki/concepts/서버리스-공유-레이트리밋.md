# 서버리스 공유 레이트리밋

> Upstash Redis REST 파이프라인(INCR + PEXPIRE NX + PTTL) 고정 윈도우 카운터 + 인메모리 폴백. 서버리스에서 인스턴스별 인메모리 리미터는 무용지물이라 공유 저장소가 필수.

## 무엇 / 언제 쓰나
Vercel/Lambda 등 서버리스에 로그인·공개 쓰기 엔드포인트 레이트리밋을 붙일 때. SDK 의존성 없이 `fetch`만으로 동작.

## 정본 구현 (canonical)
- `massage/src/lib/security/rate-limit.ts:204` — `checkSharedRateLimit`: REST `/pipeline`으로 `INCR`→`PEXPIRE NX`(첫 증가에만 TTL)→`PTTL`, `AbortSignal.timeout(2s)`, 실패 시 `null` 반환해 인메모리로 폴백.
- `massage/src/lib/security/rate-limit.ts:164` — `findPrefixedRestConfig`: Vercel 마켓플레이스가 붙이는 커스텀 접두사(`<prefix>_KV_REST_API_URL`) env를 접미사 매칭으로 탐색. 표준 이름 하드코딩하면 프로드에서 연결 실패함(실사례).
- `massage/src/lib/security/rate-limit.ts:39` — `getClientIp`: 플랫폼 헤더(`x-real-ip`/`x-vercel-forwarded-for`/`cf-connecting-ip`) 우선 — `x-forwarded-for` 좌측값은 클라이언트 위조 가능.
- `massage/src/lib/security/rate-limit.ts:60` — `createMemoryRateLimiter`: 만료 버킷 주기 스윕 포함 폴백/테스트용.

## 다른 구현 / 변형
- IP 버킷 + 크리덴셜 버킷 이중 키: `rate-limit.ts:257` `buildAuthRateLimitKey` (routeKey:IP[:credential]).

## 주의점 / 함정
- 응답 헤더에 `X-RateLimit-Scope: shared|instance`를 넣어 프로드에서 어느 경로가 작동 중인지 관측 가능하게 할 것 (`rate-limit.ts:199`).
- Redis 장애 시 폴백은 "인스턴스별"이라 한도가 사실상 N배로 풀림 — 보안 민감 경로면 폴백 시 로깅 필수.
