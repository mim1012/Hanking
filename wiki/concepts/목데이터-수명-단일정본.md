# 목데이터 수명 단일정본 (Mock의 수명)

> UI mock 데이터는 화면 검증·클라이언트 승인용 임시 산출물이며, **DB에 시드된 순간 죽는다** — 이후 값의 입력구는 관리자 화면 하나, 복구 정본은 마이그레이션 하나로 못 박는 원칙.

## 무엇 / 언제 쓰나
프론트를 mock으로 먼저 만들고 백엔드를 뒤에 붙이는 모든 수주/병렬 개발 프로젝트. "mock→real 전환이 끝났는데 mock 파일이 살아남아 정본 행세"를 하면 같은 값이 여러 곳에 손으로 적히는 드리프트가 시작된다. 전환 완료 시점에 이 원칙으로 mock의 사망을 선언한다.

## 정본 구현 (canonical)
- `BAGJO1/AGENTS.md` §4 「원칙 0 — Mock의 수명」 — 규칙 원문(예외 목록 관리 포함: seed-병합이 설계인 reviews/qna, config 기본값 전용 homeContent/survey는 명시 예외로만 허용, "예외 추가 = admin 편집 경로 먼저").
- 집행 3종 세트(BAGJO1, 2026-07-17 be/kill-static-seed-canon 머지로 검증):
  1. **mock 파일 삭제** — `src/data/{products,brands}.ts` 제거, 값 입력구를 `/admin` 하나로 축소.
  2. **재도입 기계 차단** — `BAGJO1/eslint.config.mjs:22` `no-restricted-imports`(`@/data/products`·`@/data/brands` import = 에러) + CI lint required check.
  3. **복구 정본 재지정** — 파일이 아니라 `supabase/migrations/`(최초 시드 0004b + 전량 재시드 0018 + 정정분)를 `scripts/apply-migrations.mjs`로 재생.

## 다른 구현 / 변형
- 콘센트 파사드([[project-BAGJO1]] `storage.ts`)와 짝으로 쓴다 — 콘센트는 *읽기 경로*의 드리프트를, 이 원칙은 *시드/정본 레이어*의 드리프트를 막는다. 읽기만 막으면 드리프트는 사라지지 않고 lint·테스트·CI가 없는 시드 레이어로 이사한다.

## 주의점 / 함정
- **"복구용으로 남겨두자" 명분** — mock를 살려두는 단골 논리. 이 명분이 BAGJO1에서 mock 파일을 "재시드의 정본"으로 승격시켰고, 같은 값이 ① 정본 파일 ② 손 타이핑 시드 SQL ③ admin이 실시간 수정하는 라이브 DB 세 곳에 적히게 됐다.
- **시드 레이어 드리프트는 조용하다** — 화면 레이어와 달리 빌드도 테스트도 안 깨진다. BAGJO1 실측: 정적↔DB 불일치 수습 마이그레이션 0014~0018이 연쇄로 필요했고, 끝내 프로덕션 값을 파일에 **역기입**(0035 국면)하는 역전까지 발생.
- **예외 목록은 설계도가 아니라 남은 공사 목록** — "아직 admin 화면이 없어서" 파일에 남은 도메인은 예외가 아니라 미완이다. 예외를 늘리려는 압력은 "관리자에 그 필드가 없다"는 신호.

## 배제된 접근 (dead-end)
- **읽기 경로 lint만으로 막기** — BAGJO1이 먼저 시도한 경로(`no-restricted-imports`로 컴포넌트의 `@/data/*` import 차단). 화면 드리프트는 잡았지만 mock 파일 자체가 살아 있는 한 시드·재시드가 파일을 계속 정본으로 취급했다 → 파일 삭제 없이는 미봉책. 삭제+입력구 단일화까지 가야 종결.
