# 반응형-오프캔버스-모바일

> 데스크톱 다중 컬럼 웹앱을 폰(≤640px)에서 쓸 만하게 만드는 CSS-우선 반응형 레이어: 사이드바를 오프캔버스 슬라이드 패널로, 상세 패널을 바텀시트로, 터치타깃·입력창을 손가락+iOS 규격으로 전환.

## 무엇 / 언제 쓰나
- 데스크톱에서 2~3 컬럼(사이드바 + 리스트 + 상세)으로 짠 로컬 웹앱/대시보드를 **프레임워크 없이** 폰까지 대응할 때.
- 핵심은 미디어쿼리 티어 3단으로 나누는 것: 데스크톱(그리드 전체) → 태블릿(`≤900px`, 컬럼 축소 + 상세 바텀시트) → 폰(`≤640px`, 리스트 단일 컬럼 + 사이드바 오프캔버스). 폰 티어는 태블릿 티어 **뒤에** 두어 우선 적용시킨다.
- JS는 최소만: 오프캔버스 토글 3개 리스너 + Esc 우선순위 처리. 레이아웃 전환 자체는 전부 CSS.

- **오프캔버스 사이드바** — `style.css:712-727` — `.sidebar{ position:fixed; left:0; width:min(300px,84vw); transform:translateX(-100%); transition:transform .2s }` + `.sidebar.open{ transform:translateX(0) }`. 데스크톱 기본값에선 토글/백드롭/닫기 버튼을 `display:none`으로 숨김(`style.css:310-320`).

- **바텀시트 상세 + 그랩핸들** — `style.css:759-781` — `.drawer.force-show{ inset:6% 0 0 0; border-radius:14px 14px 0 0 }` + `::before` 그랩핸들 바(`:764-775`, `position:sticky` 40×4px), 닫기 버튼 40×40 터치타깃(`:777-781`).
- **터치타깃 + iOS 줌 방지** — `style.css:784-817` — 행 `min-height:48px`(`:784-788`), 버튼 `min-height:40px`(`:794-796`), 탭·체크박스 확대; **모든 입력창 `font-size:16px`**(`:803-813`)로 iOS 포커스 자동확대 차단; 좁은 폰에선 `.row-source{ display:none }`(`:815-817`)로 이름/설명 폭 회수.

## 주의점 / 함정
- **iOS 포커스 확대 줌** — 입력창 `font-size`가 16px 미만이면 iOS Safari가 포커스 시 화면을 확대해 레이아웃이 튄다. 폰 티어에서 `input,select,textarea`를 일괄 16px로 올려야 한다(`style.css:803-813`). 데스크톱 토큰(`--fs-base` 13px 등)을 그대로 두면 재현됨.
- **사이드바 상시 점유로 리스트 짓눌림** — 데스크톱 사이드바 폭을 그냥 줄이기만 하면(예: 230px→180px) 390px 폰에서 리스트가 ~200px로 눌린다. 폭 축소가 아니라 **오프캔버스로 흐름에서 빼야** 리스트가 전체폭을 쓴다.
- **터치타깃 <44px** — 데스크톱 기본 행/버튼 패딩(8px, ~36px 높이)은 손가락 탭에 작다. 폰 티어에서 행 48px·버튼 40px로 키운다.
- **fixed 자식이 잘리는 조건** — 오프캔버스 사이드바·백드롭은 `position:fixed`라 조상에 `transform`/`filter`/`will-change`가 있으면 뷰포트가 아니라 그 조상 기준으로 잡혀 잘린다. claude-cockpit은 `main`에 `overflow:hidden`만 있고 transform이 없어 안전(단순 overflow는 fixed를 자르지 않음).
- **미디어 티어 순서** — 폰 블록(`≤640`)을 태블릿 블록(`≤900`) 앞에 두면 둘 다 폰에서 매치될 때 뒤의 900 규칙이 이겨 오프캔버스가 깨진다. 반드시 좁은 티어를 뒤에.

## 배제된 접근 (dead-end)
- **`≤900px` 축소-only 단일 티어** — 최초 구현은 폰까지 하나의 `@media (max-width:900px)`로 처리해 사이드바를 180px로 줄이고 2컬럼을 유지했다. 태블릿엔 괜찮았으나 실제 폰 폭(≈390px)에선 리스트가 짓눌리고 터치타깃·iOS 줌·검색 접근성이 모두 미해결이라 **폰에서 사용 불가**로 판정, ≤640 별도 티어(오프캔버스 + 16px 입력 + 터치타깃)로 교체했다.
- **실기기 시각 검증은 아직 미완** — node --check 통과 + 로컬/Tailscale HTTP 200 서빙 + 마크업/규칙 존재까지 확인했으나, 실제 폰 브라우저에서의 렌더 시각 확인은 이 세션 시점 대기 상태(헤드리스 세션에서 브라우저 구동 불가). canonical 지정은 "구문·서빙 검증" 수준이며, 실기기 확인 후 이 줄을 갱신할 것.
