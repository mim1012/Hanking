# 순위체크 대시보드·배포 게이트

> Sellermate 순위체크 Android/Chrome 러너와 운영 대시보드를 새 세션에서 이어갈 때 적용하는 경계·검증·배포 규칙.

## 프로젝트 정체성

- 사용자에게 보이는 제품명은 **Sellermate**다.
- `D:\Project\adpang-production`과 Vercel 프로젝트 `adpang-production`은 호스팅 저장소 이름일 뿐, 화면 라벨을 AdPang으로 바꾸는 근거가 아니다.
- Android OTA(`rankchecker_releases`)와 Sellermate 웹 대시보드는 서로 다른 릴리스다. APK v46 배포 여부와 웹 대시보드 배포 여부를 별도로 판정한다.

## 구현 경계

- Android WebView의 직접 fetch/DOM 폴백과 ADB 일반 Chrome CDP 러너는 같은 경로가 아니다. Chrome CDP 카나리가 성공해도 WebView APK가 성공했다고 추론하지 않는다.
- 네이버 API가 418/429·보안 문서·빈/이상 응답을 주면 `NOT_FOUND`로 확정하지 않는다. 검증된 Chrome 경로에서는 실제 브라우저 페이지네이션과 DOM을 사용하고, WebView 경로는 별도 카나리로 증명한다.
- 정본 데이터 경로는 `sellermate_naver_place_all/rank-check/android/extract-rank.ts:366,454` + `sellermate_naver_place_all/rank-check/android/cdp.ts:244`의 Chrome DOM 폴백과 `sellermate_naver_place_all/rank-check/utils/save-rank-to-slot-naver.ts:72-74,333-400`의 history read-back 계약이다.

## 대시보드 데이터 계약

- API 진입점은 `D:\Project\adpang-production\src\lib\android-admin-server.ts:254-259`의 `rankchecker/snapshot`이다.
- 장비명은 `rankchecker_devices.metadata.device_name`을 우선하고 `equipment_name`을 보조로 사용한다(`android-admin-server.ts:1803-1817`). 값이 없을 때만 `장비명 미보고`로 표시한다.
- 장비명과 `worker_id`는 다른 식별자다. 카드는 장비명을 주 표시로, `worker: ANDROID-...`를 보조 식별자로 보여줘야 한다(`RankcheckerDeviceDashboard.tsx:366-407`).
- Sellermate 화면은 `순위체크 봇 관리` 링크(`SellermateSidebar.tsx:153-162`)와 `k그룹 · 순위체크` 화면(`page.tsx:1878-1901`)으로 연결한다.

## 완료 게이트

1. **순위 데이터**: 정본 history INSERT 후 대상 ID·시각·기대 건수를 read-back한다. `previous_rank`, `current_rank`, `rank_diff`, `rank_change`, `UP/DOWN/SAME` 방향도 함께 대조한다. heartbeat, job success, queue 삭제, INSERT 응답만으로 완료 선언하지 않는다.
2. **대시보드 API**: 인증된 런타임에서 `rankchecker/snapshot`의 실제 DB 응답을 읽고, 비인증 요청은 401로 거부되는지 확인한다.
3. **UI**: 인증 화면에서 데스크톱과 390px 모바일을 매번 새로 캡처한다. `scrollWidth`가 `clientWidth`보다 크지 않고, CJK 라벨이 잘리지 않아야 한다.
4. **배포**: dirty worktree에서 바로 올리지 말고 변경 파일만 격리한 배포 worktree를 만든다. Vercel 원격 build가 성공하고 deployment가 `READY`여야 한다.
5. **증거 신선도**: 제목·CSS·데이터·레이아웃을 수정하면 기존 PNG를 재사용하지 않는다. 수정 이후 캡처와 DOM 측정 JSON을 새로 만든다.

## 반복 실패를 줄이는 규칙

- 같은 WebView 폴백을 세 번 이상 보정해도 보안 문서가 계속 나오면 코드 미세조정을 중단하고 Chrome CDP 또는 다른 세션 경계로 전환한다.
- 로컬 Next build가 Node/페이징 파일 부족으로 실패하면 동일 명령을 반복하지 않는다. 변경 파일 ESLint/diff 검증 후 Vercel 원격 build를 사용하고, 로컬 리소스 실패는 production build 실패와 구분한다.
- 기존 worktree에 다른 변경이 많으면 커밋·reset으로 정리하지 않는다. 배포 산출물만 별도 worktree에서 만들고 원본 dirty 상태를 보존한다.
- “최신”이라는 말은 릴리스 테이블·기기 telemetry·라이브 chunk·브라우저 화면을 각각 read-back한 뒤에만 사용한다.
